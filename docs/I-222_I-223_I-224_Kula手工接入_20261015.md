## 一步怎样执行

1. 五次真实预热仍走旧初始化路由，每次成功步分别登记；新路径的预热或订阅失败终止初始化。
2. 预热后创建共同节律与合作生成对象。正式步前，从已排队需求生成同一帧，按真实名称发送 float32 原生目标；必需求力输入先检查，失败不进入后续物理步。
3. 首帧已发布且写入成功后，气动回调绑定这个运行对象。回调只读动作帧，重复调用不会推进节律、DMP 或真实事件。
4. 物理步后，控制器输出、手动输入和真实备用定高快照显式排入下一步。频率沿手动、自动有效频率、备用、基准的顺序选择；尾舵保留自动输出存在时优先的既有关系。

普通位置目标写入与直接钉住分别执行。钉住实际发送位置、速度和目标；后一个操作失败时保留前一个操作的成功回执。模拟后端通过理想随动 API 外壳调用同一个关节适配器，并明确标注 `ideal_state_written`，不冒充真实伺服跟踪。

释放在旧段的快照状态写入后清除需求/事件队列、重建节律和基元初值并增加段号，下一步生成新段首帧；已有执行失败不能被释放操作悄悄清除。模拟后端同进程复位创建新的运行身份并关闭旧日志。

## 秒滞后与导数

现行负 `PITCH_LAG_S` 已实际接通。查询 `t-lag` 时，正滞后只查真实服务历史；负滞后在服务副本中执行已知频率程序和事件，未知未来闭环需求保持当前值。历史不足、无法解释的事件内插或超出声明的预测预算会明确失败。

新合作入口声明 `backward_difference_v1`：频率/参数更新导致精确导数不可用时，在非事件、非硬门控边界，按已采用目标样本做后向差分，标记为 `declared_approximation`。它表达目标程序的数值导数，不是实测关节速度/加速度，也不作为执行器带宽或飞行性能证明。原有精确导数仍保留。

真实解析接缝、硬门控边缘和真实事件不会用普通零导数掩盖。明确零门控采用中立保持目标，时钟继续；硬切换当步导数不可用，求力前检查会停止该新路径。要让此类切换连续运行，需要选择并登记连续过渡程序，不能把本轮的硬切换候选说成已经具备该能力。

## 求力和八点窗口

支持的实际模型类为既有 `FlapperAeroModel` 和 `SaneDickinson3DModel`；当前首个执行程序绑定 `aero` 俯仰模式。未适配的模型或俯仰模式明确拒绝。

外部入口直接采用帧内拍动角、扭转角和必需导数。旧翼对象只在隔离范围内由物理尺度视图替代，不再掌握波形；原对象在成功和异常后均恢复。右翼偏移已在子时钟中采用，求力侧不再叠加。

八点算子仍为 `origin + k * left_reference_period / 8`。完整步在副本中走同一运行时，最后一个分数时间查询仅在提供者副本中消耗对应规范区间。模型缓存另用隔离副本，真实状态和真实事件不变。左右差频、单次过渡和跨事件场景统一命名为**有限左翼参考窗口**，不宣称完整共同周期平均。

暂存、合并、缩放、接口接受和接口失败保留来源帧列表、回调时间及抑制标志。真实 PhysX 接口接受后，求解器实际消费步仍记 `unknown`；模拟积分器成功执行后才登记其明确的消费步。折翼几何未进入现有力模型，如实记录为未消费。

## 记录边界

- 关节请求、原生数值、逐操作成功/失败、尾舵结果、配方/参数/段/帧身份分列。
- 新配方关闭详细记录后，最小身份、需求及采用摘要、目标与消费结果仍保存；每个运行另存完整配方、归一化、周期/启动 DMP 权重和源版本。
- 记录写入失败与执行失败分别保存。已经成功的原生接口副作用不回滚；记录故障阻止下一物理步，关闭放入受保护收尾。
- 既有实验资格、科学判据和二进制格式不在本轮重建。
