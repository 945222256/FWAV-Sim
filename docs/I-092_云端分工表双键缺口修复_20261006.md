# I-092 云端分工表双键缺口修复（2026-10-06）

> 事项 I-092：心跳上行写 lanes_conf 镜像键，快照下发读 lanes 权威键，
> 云端权威分工表无代理令牌写入路径。本文件为交付记录。

## 一、缺陷机制解剖

分工表在云端配置库存了两把键。心跳上行把本地路线表写进镜像键
lanes_conf，快照下发从权威键 lanes 读，两者永不相交：本地修订上不去
读侧。更重的是反向事故路径：本地缓存同步在强拉时把快照的权威键内容
整档写回本地 lanes.json（缓存映射表里 lanes 键正指向本尊文件），而
强拉分支先于心跳执行——云上旧表会在心跳上行前冲掉本地新表，总部
今晨的路线表修订就是这样丢的。

## 二、修复内容（四处）

其一，服务端心跳路由：上行统一写权威键 lanes，新旧两种载荷形态
（直接路线字典与旧包裹结构）都归一到权威键，不再写镜像死键。其二，
服务端状态接口：泳道数据只读权威键，删除镜像键优先的旧读法。其三，
本地同步客户端：心跳载荷携带本地路线表上行，本地 lanes.json 作为
登记源每次心跳镜像上行，云端漂移自愈；同步顺序改为一律先推后拉，
冷启动强拉也先上行，堵住反向冲掉路径。其四，服务器侧一次性清理：
镜像死键清除（清除前留数据库全量备份），权威键持有完整八路线表。
修改文件为 cloud_board/api_agent.py、cloud_board/webui.py、
items_registry/cloud_client.py 与 items_registry/lanes.json。

## 三、八路线表的复原

本地 lanes.json 在事故后只剩六条，总部含六队七队的修订从未入库。
按在案证据复原两条新线：六队强化学习线，rl 目录自一路线划出（协作
架构在案），使命为生成式策略与强化学习微调与逆映射部署；七队导航
合龙线，定义出自事项 I-091 的机主说明，使命为同步目录常驻岗位与
合龙准备。复原后本地八条，与云端权威键逐字一致。

## 四、判据逐条验证

判据一，代理令牌可写权威分工表：过。以代理令牌经心跳路由上行写入
权威键，接口返回成功，快照即反映。判据二，上行与下发读写同一个键：
过。上行写权威键、快照与状态接口读权威键，代码两处同键；镜像死键
已清除。判据三，修复后云端看板与手机端泳道显示全部八条路线，与
本地 lanes.json 一致：过。快照权威键八条与本地逐字一致；状态接口
泳道数据八条；新版前端泳道列由事项路线字段动态生成，六队七队事项
自动成列。另冷启动顺序纪律实测：强拉同步后本地仍为八条，反向冲掉
路径已堵。
