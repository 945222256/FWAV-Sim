## 二、能力一：自然语言生成工作流（对应依赖图接力编排）

主张复核：属实。

核心接口是 Eko 类的三段式生命周期，位于 packages/eko-core/src/agent/eko.ts：

1. `generate(taskPrompt, taskId)` 第 33 行起：自然语言进，工作流对象出。
   生成过程由 Planner 承担（agent/plan.ts），生成的 Workflow 类型定义在
   types/agent.types.ts 第 56 行起，节点分 normal、forEach、watch 三类，
   步骤文本节点可程序直接改写。
2. `modify(taskId, modifyTaskPrompt)` 第 61 行起：对既有工作流重规划，
   支持任务进行中调整。
3. `execute(taskId)` 第 81 行起：执行；`run()` 第 113 行起是生成加执行的
   合并便捷口。

对本项目的意义：generate 与 execute 分离意味着依赖图接力可以在工作流对象
生成后、执行前，由编排层程序化改写节点（例如把节点动作替换为宿主服务
操作），这正是接力编排需要的形态。

## 三、能力二：人工干预机制（对应控制台干预面板与交接卡）

主张复核：属实，且比路线图描述的多一层。

干预通道有两层，互相独立：

1. 进程外控制通道，packages/eko-core/src/agent/eko.ts：
   - `pauseTask(taskId, pause, reason, abortCurrentStep)` 第 348 行：
     暂停与恢复共用一个入口，可连带中止当前步骤；
   - `abortTask(taskId, reason)` 第 336 行：中断，内部走 AbortController。
2. 工作流内人机交互工具，packages/eko-core/src/tools/human-interact.ts：
   智能体可在步骤中主动发起 confirm（确认）、input（输入）、select（选择）、
   request_help（求助）四类人工交互，经 EkoConfig 的 callback 且回调给宿主。

快照恢复机制，packages/eko-core/src/memory/snapshot.ts：task_snapshot
工具把任务执行史摘要归档，中断后继续时注入续跑提示（第 52 行起的原文
摘录：The current task has been interrupted. Below is a snapshot of the
task execution history）。注意其形态是提示词级摘要注入，不是外部持久
工件；与本项目交接卡（logs/handoff/ 文件）对账时，交接卡仍由我方守门
进程落盘，快照只作续跑上下文，两者不能划等号（此为对路线图的修正一）。

## 四、能力三与能力四：多模型配置、多智能体并行

多模型配置主张复核：属实。

- 提供方枚举 openai、anthropic、google、bedrock、openrouter、
  openai-compatible，types/llm.types.ts 第 25 至 31 行；
- LLMs 类型是 default 加任意命名键（types/llm.types.ts 第 56 行起），
  每个智能体可按名字选用自己的模型（agent/base.ts 第 59 行 Agent.llms 字段）；
- 底层经 AI 软件开发工具包各提供方适配器接入（eko-core/package.json
  依赖清单），不含浏览器栈。

多智能体并行主张复核：属实。

- 依赖感知的层级树：common/tree.ts 第 8 行 buildAgentTree 按每个智能体的
  dependsOn 集合逐层归并，同层智能体即并行集合（第 40 至 66 行）；
- 并行执行证据：agent/base.ts 第 220 至 228 行，满足并行条件的调用用
  Promise.all 同时发出。

## 五、接入方式结论与两处修正

结论：路线图第三期的接入映射成立，且实现面比预想轻。

1. 只用 eko-core。eko-nodejs 依赖 playwright、puppeteer 全套浏览器栈
   （eko-nodejs/package.json 依赖清单），本项目无浏览器智能体需求，
   编排器以 Node 直接引 eko-core 即可，不引入浏览器依赖（此为对路线图
   的修正二：路线图未区分 core 与 nodejs 的依赖重量）。
2. 宿主服务五操作（status、dispatch_new、dispatch_resume、index_register、
   kill_child）包装为 eko-core 的 Tool 接口实现（types/tools.types.ts
   第 68 行起，name、description、parameters、execute 四件），挂到自定义
   施工调度智能体上（Agent 构造参数 tools 字段，agent/base.ts 第 68 行起）。
   宿主服务指令口是本机回环逐行 JSON，包装层是纯胶水。
3. 控制台两动作（注入、停止）映射干预双层：停止映射 abortTask，注入映射
   pauseTask 后经 dispatch_resume 续送；快照与交接卡按第三节结论分工。
4. 模型接入的前提是提供方鉴权配置自持，该前提由路线图第二期（I-161
   自有驱动器验证线）先行解决，I-162 施工前依赖其结论。
