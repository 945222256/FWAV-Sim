## 一、写入机制查明

任务索引指文件 C:\Users\Anni\.zcode\v2\tasks-index.sqlite 的 tasks 表，
机主客户端的侧栏任务列表从它读取。会话库指客户端后端维护的会话记录
存储，目录 C:\Users\Anni\.zcode\cli\。

唯一写入方是桌面客户端进程。证据一：客户端安装包 app.asar 内含
tasks 表全部建表、迁移与读写代码，检索特征列名 searchable_text 命中
三十六处；命令行组件 zcode.cjs 同检索零命中。证据二：索引文件修改
时间与客户端动作时刻吻合，本会话行的写入时刻为十六时十九分二十四秒，
与机主重启客户端的时刻一致。不存在独立的同步器进程；同步是客户端
内部的投影行为：客户端通过版本四订阅接口 subscribeSessionsIndexV4
从其后端读取会话摘要，再把摘要投影为任务行。

写入时机共四类。第一类，客户端启动或恢复时对基线快照做补齐，函数
名 seedMissingRowsFromInitialSnapshot，日志文案为首次 sessions-index
基线补齐 task index；这正是重启后条目出现的通道，也是派发会话在
客户端运行期间不可见的直接原因。第二类，在线摘要事件触发状态与标题
补丁；实测该路径对客户端不观测的新会话不插入新行：本会话十五时十七
分派发，客户端运行中六十二分钟无行；对照实验中无界面参数与
界面参数 desktop 两组测试会话各观察六十秒与一百二十秒，均无行。
第三类，用户在客户端内的置顶、改名、未读、归档操作。第四类，打开
数据库时执行带校验和的迁移，迁移表 tasks_schema_migration 现存三条
记录。全部写入经串行队列与立即写事务，日志模式为预写日志，时间戳
为毫秒整数。

字段与必填项：物理非空列全部带默认值，最小可行行只需工作区键、
工作区路径、任务号、标题、建立时刻、更新时刻六项；客户端投影读取
的业务必填项还有状态、提供方与 meta_json 嵌套节，该节含任务号、
追踪号、标题、工作区路径、建立时刻、更新时刻、模式、提供方、状态
九键。唯一约束为工作区键加任务号。状态语义：状态值由客户端观测到的
会话相位投影得出；从未被客户端观测的会话，状态取自基线快照时刻的
摘要相位。本会话十六时十九分快照时恰处回合间空闲，故登记为
completed；九月二十七日一条会话至今挂着 running，证明客户端不会
主动校正未观测会话的状态。结论：状态失真是架构性的，跨客户端进程
运行的会话其真实运行态不进客户端的在线摘要流，任何登记动作都不能
让客户端持续跟踪它。

## 二、三案三栏评定

甲案，派发工具直接写索引库。数据损坏风险为中低：预写日志保证单条
写入原子性，唯一约束防重复，但客户端持有内存缓存，外部行绕过其
串行队列，客户端何时拾取不确定，字段形态错误可能令界面渲染异常。
与客户端并发冲突风险为中：单写者语义下双方短事务互锁，实验五实测
第二连接在立即写事务期间被锁，须设忙等超时并重试。版本升级脆性为
高：表结构由校验和迁移体系管理，客户端升级可加列或改投影不变量，
外部硬编码列集会静默漂移。

乙案，寻找官方登记或同步接口。当前版本不存在该接口：命令行协议有
会话建立与任务查询方法，但都作用于会话库，不触客户端索引；界面
参数 desktop 的对照实验证明派发面无法借道；客户端内部的登记函数
无对外调用面。三栏在不存在的前提下不适用；若官方未来提供接口，则
三栏风险全部由官方维护兜底。

丙案，由常驻宿主服务承担登记动作。写入路径与甲案相同，三栏风险
同源；差别在执行者：宿主服务常驻、单实例、开机自启，可集中实现
形态校验、忙等重试与升级自检，工程可控性显著优于一次性派发脚本。
数据损坏风险为低，并发冲突风险为中低，版本升级脆性仍为高。

## 三、结论与推荐

结论：可登记但需防护。推荐丙案为载体，即把登记封装为宿主服务的
一个操作，防护清单六条如下。其一，只插入不更新不删除，唯一约束
冲突即视为已登记，幂等。其二，最小列集加完整 meta_json，九键形态
与客户端写入器一致。其三，忙等超时不低于八秒，失败进重试队列，
只在派发回读命中后登记。其四，登记状态一律用 completed，与客户端
对未观测会话的语义一致；写 running 会永久滞留，九月陈旧行为证。
会话真实运行态以会话库为准，索引不承担真值。其五，客户端每次
升级后跑一次形态自检，比对客户端自写行的列集。其六，登记后行何时
出现在侧栏未经实测，纪律禁止动原库；判据一即为此设，若实测不满足
则退化为登记后需一次客户端重启或工作区重新激活。

## 四、验收判据草案

一，测试会话经宿主服务派发并回读命中后三十秒内，任务索引出现该
任务号的行，查验方式为只读轮询。二，幂等性：同一会话重复登记不
产生第二行。三，原子性：登记期间强制终止宿主服务进程，索引库
完整性检查 pragma integrity_check 通过。四，无干扰：登记后客户端
对该行的置顶、改名、归档操作全部生效，由机主在客户端人工核验一次。
五，升级自检：客户端版本变更后，形态自检脚本对客户端自写行比对
通过。六，状态语义：登记行状态为 completed，文档声明运行态真值
在会话库。
