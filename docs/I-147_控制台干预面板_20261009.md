# I-147 控制台干预面板（2026-10-09）

> 事项 I-147：注入消息与停止会话两动作。依据方案草案与机主说明。
> 施工：L5 队。判据两条冻结于事项登记。

## 一、实现

三层链路。前端：观察窗卡片注入与停止按钮启用，点击弹确认层
（动作名、会话号、注入正文可填、理由必填、执行说明），确认后调
/api/console/action；云端：action 接口写 console_events 台账并为
inject 与 stop 各落一条 console_tasks 动作任务（载荷含操作与正文）；
本机：采集代理每周期以显式认领参数取走任务，注入经宿主服务恢复后
发送（带回读核验），停止经宿主服务终止驱动回路（I-126 定论的
有效通道，看护线程随后自愈拉起协议子进程），执行结果回填任务行
（done 或 failed 加摘录）。

云端任务通道配套两处修订：任务认领显式化（claim=1 参数才转移
pending 到 taken，不带参数为只读巡查，防止任何读取方偷走任务），
新增结果回填口 /api/console/tasks/result。实施中发现初版端点
读取即认领，验收脚本自己的轮询把任务偷走致执行者饿死（僵尸任务
一号经结果口如实标 failed 留档），修订后全链路闭环。

## 二、判据核验（全链路实测 logs/i147_live_test.py）

判据一（注入经宿主服务恢复后发送、停止经宿主服务终止驱动回路，
各实测一次成功）：以全新测试会话 sess_2d100818 为目标，注入任务
三号执行结果 done，摘录"注入经宿主服务恢复后发送，回读核验=True，
accepted=True"；停止任务四号执行结果 done，摘录"停止经宿主服务
终止驱动回路，killed=True"。证据 logs/i147_live_test_result.json。

判据二（两动作先弹确认再执行并写入事件台账）：确认层界面实测
（logs/i130_check/i147_modal_check.js 输出：标题含动作名与会话号、
理由输入在位、执行说明"确认后经宿主服务对该会话恢复后发送，回读
核验"）；台账由 action 接口强制理由必填写入 console_events，两次
实测的 recorded 应答与任务派生在结果文件留痕。

## 三、边界

其一，停止通道按 I-126 定论终止协议子进程，宿主服务派发的全部
会话驱动随之停止、看护三秒自愈；对非宿主派生的会话无驱动可停，
结果摘录如实表述。其二，任务认领的单写者纪律依赖同步代理单实例
（重启脚本先杀后起）；双实例并行认领的防护不在本件范围。其三，
注入正文为空时发送默认提示语；停止不区分会话所属路线（驱动回路
为本机全局），逐会话精细化停止待驱动模型改造另立项。
