# Q-040 定论：会话直送跨进程激活路径（2026-10-05，L5 实测）

## 结论

**session/resume {sessionId} 即激活方法**，实测可用。任何持久化会话
（含宿主进程已死的孤儿会话与桌面客户端创建的休眠会话）在新起的
app-server 进程里先经 session/resume 冷恢复，随后 session/send 与
session/messages 全部可用，无需常驻宿主方案。

## 实测证据（靶会话 sess_e3b4742e，其创建进程已死）

1. 新进程 session/list：靶会话在库，status=idle；
2. session/resume {sessionId}：方法存在、返回成功，并伴随服务端反向
   请求（session/requestRuntimePreferences 与
   interaction/requestOfficialMcpAuthHeaders）按既有应答模式处理；
3. 激活后 session/send：accepted=true；
4. session/messages 回读第一轮即命中新增测试消息（4660 字节，
   含历史消息与新消息）。
   证据文件：logs/q040_probe_evidence.json（含全部收发转录），
   探测脚本 tools/probe3.mjs。

## 边界与建议

- 冷恢复加载的是库内快照：对**正被桌面客户端实时持有的活跃会话**，
  双进程同时驱动有状态分叉风险，定向发送应等宿主侧空闲或走宿主自身
  通道；本定论覆盖"休眠会话激活"，即 I-059 派发场景的全部需求
  （派发会话由协议进程自建自用，无宿主竞争）。
- session/resume 之前未见于任何探测记录，属本次新探明方法；与方法族
  session/activate、session/attach 均不存在形成对照。
- 建议指挥部将 Q-040 按本定论批准关闭或驳回合并至 I-059 增量项，
  L5 不代行审批。
