# I-143 控制台采集代理扩展（2026-10-09）

> 事项 I-143：同步代理增会话库只读采集，五秒周期上行会话快照。
> 依据：编排控制台_技术方案与立项草案_20261009.md 第二节采集层与
> 第三节数据字典。施工：L5 队。判据三条冻结于事项登记。

## 一、实现

其一，采集模块 lp_sync/console_collector.py：五秒周期只读打开会话库
（只读统一资源标识符连接，写动作零）；活跃窗口三十分钟内的本工作区
会话（G:\Playground 与 isaac_flapper_sim 两个目录值）逐行生成快照；
占用百分比按冻结口径取该会话最近一次已完成模型请求的 input_tokens
除以 console.context.token_cap（参数登记库在册值，经 registry 模块
读取，不抄写数值）；状态按最近活动分档（九十秒内在干活，窗口内
更早为空闲）；队伍与事项映射取 dispatch_registry.json 三元组；
每行携带四字段出处指针指向会话库最新已完成行；经既有代理令牌
上行云端 /api/console/ingest。断网不入断网队列（快照是瞬时状态，
最新一遍覆盖旧值），失败在时间线留痕并下周期重推。

其二，派发三元组登记：宿主服务 dispatch_new 增 item_id 与 lane 可选
参数，派发即写 lp_sync/dispatch_registry.json（原子写）；历史派发
由 backfill_dispatch_registry.py 按 logs/dispatch_session/ 回填，
路线优先取留痕文本，缺失时按事项总账反查，三笔历史全部回填并标
origin=backfill；本会话三元组人工修正为 L5 与 I-143（早于机制派生，
标 manual_correction）。

其三，接线：sync_agent 启动时拉起采集守护线程（导入失败只降级不拖垮
账本同步主职能）；判据一时间线落 logs/console_collector_timeline.jsonl
（只增不改）。

## 二、判据核验

判据一（五秒周期连续一小时推送无断档）：监控进程
logs/i143_c1_monitor.py 于 2026-10-09 十时五十五分脱会话启动，每小时
十分钟终检：本地时间线条数须不少于六百、相邻推送最大间隔须不大于
十一秒、错误行为零、云端抽查滞后峰值须不大于三十秒，四项全过才判
过；结论落 logs/i143_c1_verdict.json。采集线程于十时五十三分起实测
五秒节奏在推（时间线首三行间隔五秒，每轮受纳八行）。

判据二（抽样十条上行数据与直读会话库逐字一致）：独立对账脚本
logs/i143_c2_sample.py（不经采集模块，直写原始查询）跨两个采集周期
取十六条样本，十五条逐字段全对（占用百分比、最近活动时刻、路线、
事项号四字段），超出十条要求；唯一失配为云端残留行 sess_i142_test

## 三、新发现与边界

新发现一（待入册）：云端 console_sessions 表存有残留测试行
sess_i142_test，本地会话库无此会话，将永久占用活跃计数并在页面显示
幽灵卡；建议三队清理并为 ingest 加会话存在性校验或快照过期机制。
新发现二（待入册）：非宿主服务派生的会话（各队并行会话）无派发
留痕，路线与事项映射为空，页面显示为匿名卡；如需补全须指挥部定
回填口径。边界：下查回填（console_tasks 取走与结果回填）接口三队
尚未给出结果回填通道，属 I-148 范围，本模块未实现取走逻辑；归档
抽屉数据来自三期切换事件，本模块只上行活跃会话。
