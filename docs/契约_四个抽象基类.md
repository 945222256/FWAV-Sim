# 契约：四个抽象基类

本文为整改第六件事 T6.1 的接口冻结文档。本文定义硬件抽象层四个抽象基类的职责边界、接口签名、数据结构、与现有类的对应关系、迁移顺序与最终验收判据。

批准记录如下。二零二六年九月三十日机主下令立即开工，并批准按候选划分施工，候选划分为气动算子、执行器、状态源、仿真后端四类。施工清单 T6.1 的默认动作条款载明无人答复视为按候选划分施工。本段即该任务验收所需的批准记录。

冻结声明如下。本文与 modules/contracts.py 自批准时刻起构成接口冻结。冻结范围含类名、方法名、方法参数、字典键名、坐标系籍贯取值五项。任何冻结范围的改动属于结构契约变更，必须按决策路由第一条上报，上报必须附证据与建议，批准前不许改。无人答复时的默认动作为不改动并保持冻结现状。

## 一、术语定义

抽象基类的英文全称为 Abstract Base Class，缩写为 ABC。抽象基类是声明了至少一个抽象方法并且不允许直接实例化的类，程序只能创建其具体子类的实例。契约一词在本文中的含义为：四个抽象基类及其方法签名与数据结构所规定的唯一接口，迁移与新增实现必须遵守该接口。

气动算子的英文全称为 Aero Operator。气动算子负责计算机翼、尾翼与机身受到的气动力与气动力矩。执行器的英文全称为 Actuator。执行器负责把控制器输出映射为关节目标与舵偏。状态源的英文全称为 State Source。状态源负责读取机体与关节的状态并标注每个量的坐标系籍贯。仿真后端的英文全称为 Simulation Backend。仿真后端负责仿真世界的建立、复位、步进与关闭。

机体系的英文全称为 body frame。机体系以机体质心为原点，x 轴指向机头前方，y 轴沿左翼展向，z 轴垂直于机体对称面向上。世界系的英文全称为 world frame。世界系为仿真世界的惯性参考系，其 z 轴竖直向上。坐标系籍贯的定义为：一个物理量所隶属的坐标系的名称，契约把它记录在数据结构中名为 frame 的字段里。

悬停基准指现行悬停回归所用的基准工况与判据。持续集成的英文全称为 Continuous Integration，缩写为 CI。持续集成指提交时自动运行测试的机制。

## 二、职责边界

四个基类的职责边界如下，相邻边界互不重叠。

AeroOperator 拥有气动力求值。它接收机体状态与翼面指令，返回按部件分解的气动力与气动力矩。重力、刚体惯性、关节目标写出与力施加不属于它的职责。

Actuator 拥有控制量到执行量的映射。它接收控制器输出或手动通道输入，返回并写出九个关节的位置目标与尾翼三舵偏角，并把翼面指令转发给气动算子。控制律计算不属于它的职责。

StateSource 拥有状态读取与坐标系换算。它返回位姿、速度、角速度、关节角与关节速度，并为每个量标注坐标系籍贯。机体系与世界系的换算集中在该层。滤波后速度口径也由该层供给。

SimBackend 拥有世界生命周期与部件编排。它按次序组合其余三个部件，推进物理步并返回观测。Isaac Sim 的类型只允许出现在它的实现内部。

FlightController 不并入任何基类。它是四个契约的共同调用方，迁移的目标是让它不加修改地运行在两个后端上。

## 三、接口签名全文

权威文本为 modules/contracts.py。下列签名与该文件逐字一致；两者不一致时以代码文件为准，且该不一致本身按冻结条款上报。

### 3.1 AeroOperator

```python
class AeroOperator(ABC):
    @abstractmethod
    def initialize(self, config: dict) -> None: ...
    @abstractmethod
    def reset(self, state: dict) -> None: ...
    @abstractmethod
    def compute(self, state: dict) -> dict: ...
```

### 3.2 Actuator

```python
class Actuator(ABC):
    @abstractmethod
    def reset(self) -> None: ...
    @abstractmethod
    def apply(self, commands: dict, dt: float) -> dict: ...
```

### 3.3 StateSource

```python
class StateSource(ABC):
    @abstractmethod
    def read(self) -> dict: ...

    # 以下三项为该基类的具体方法，随契约一并冻结。
    @staticmethod
    def world_to_body(vector_world, quaternion) -> list: ...
    @staticmethod
    def body_to_world(vector_body, quaternion) -> list: ...
    @classmethod
    def verify_frames(cls, reading: dict) -> list: ...
```

### 3.4 SimBackend

```python
class SimBackend(ABC):
    @abstractmethod
    def setup(self, config: dict) -> None: ...
    @abstractmethod
    def reset(self, seed=None) -> None: ...
    @abstractmethod
    def step(self, actions=None) -> dict: ...
    @abstractmethod
    def close(self) -> None: ...
```

## 四、数据结构契约

数据结构一律为纯 Python 字典。全部结构不依赖 Isaac Sim 的任何类型，因此两个后端共用同一份结构。

### 4.1 指令字典

指令字典的核心九键为 freq、dfreq、dA、dlag、gate_L、gate_R、elevator、aileron、rudder。九键的语义与现行 FlightController.update 返回字典中的同名键一致。freq 为集体拍频，单位赫兹。dfreq 为每翼频率差动，左翼取 freq 加 dfreq，右翼取 freq 减 dfreq。dA 为翼幅差动，左翼幅值加 dA，右翼幅值减 dA，单位弧度。dlag 为翼面俯仰滞后差动，单位秒。gate_L 与 gate_R 为左右翼拍动门控，取值一表示本拍拍动，取值零表示本拍停拍。elevator、aileron、rudder 为尾翼三舵偏角，单位弧度。

### 4.2 AeroOperator 的输入与输出

compute 的 state 字典含七键。t 为仿真时间，单位秒。position_world 为长度三的世界系位置列表，单位米。quaternion_world 为长度四的单位四元数列表，元素顺序为 w、x、y、z，表示机体系到世界系的旋转。velocity_linear_world 与 angular_velocity_world 为长度三的世界系速度与角速度列表。wind_world 为长度三的世界系风速列表或 None。commands 为指令字典。

compute 的返回字典含 wing_left、wing_right、tail、fuselage、total 五键。前四键各映射一个部件字典，部件字典含 force_world 与 torque_world 两键，两键各为长度三的世界系向量列表，单位分别为牛与牛米。total 为四部件的合成。返回字典可附加 diagnostics 键，其值为实现自定义的诊断字典。

initialize 的 config 字典含 model_name 与 params 两键。reset 的 state 字典与 compute 的 state 字典同构。

### 4.3 Actuator 的输入与输出

apply 的 commands 字典含 source 键与指令体。source 取 autopilot、manual、idle 三值之一。取 autopilot 时指令体为 FlightController.update 的返回字典。取 manual 时指令体为手动通道字典，其键为 throttle、elevator、aileron、rudder、da 五项。取 idle 时指令体为空字典。

apply 的返回字典含四键。joint_targets 为九关节目标字典，九关节名为 flap_L、flap_R、twist_L、twist_R、fold_L、fold_R、tail_yaw、tail_L、tail_R，目标单位弧度。tail 为尾翼三舵偏角字典。wing_state 为含 freq_L、freq_R、gate_L、gate_R、dlag 五键的字典，供记录器落盘。mode_cache 为整数模式标记，零、一、二分别对应动力定位模式、自动驾驶仪模式与手动模式。

### 4.4 StateSource 的返回结构

read 的返回字典含九个必备键与至多一个可选键。九个必备键为 t 与八个必备状态量。八个必备状态量为 position、quaternion、velocity_linear、velocity_linear_body、angular_velocity、angular_velocity_body、joint_positions、joint_velocities。可选键为 velocity_linear_filtered，该键承载滤波后线速度口径。每个状态量映射一个字典，该字典含 value 键与 frame 键。frame 的取值以模块常量 STATE_QUANTITY_FRAMES 的声明为准，校验入口为 verify_frames。

### 4.5 SimBackend 的输入与输出

setup 的 config 字典含 physics_dt、scene、aero、assets、headless 五键。reset 的 seed 为随机种子或 None。step 的 actions 为指令字典或 None，返回值为与 StateSource.read 同构的观测字典。close 无参数无返回值。

## 五、与现有类的对应关系表

下表载明六个现有类与函数各自归入哪一层。处置动词的含义：迁入表示代码搬进该层实现；拆解表示一个类按职责分成数段分入多层；保留表示位置不动。

| 现有类或函数 | 归属层 | 处置说明 |
|---|---|---|
| FlightController | 控制律层，四个契约的共同调用方 | 不迁入任何基类。update 的输入改由 StateSource 供给，输出改交 Actuator 消费。其内部的世界系到机体系换算段与欧拉换算改用 StateSource 的字段与方法。控制律本体不加修改。 |
| FlapperAeroModel | 气动算子层 | 迁入 AeroOperator 的默认翼面实现。compute_forces 的输入输出经 state 与 result 字典转接，叶素积分与有符号来流镜像等物理保持原样。 |
| AeroModelBase | 气动算子层 | 保留为 modules/aero 包内多流型实现的内部基类，收敛为 AeroOperator 实现的内部模板。compute_forces 模板方法保留为实现细节，不进入契约面。 |
| AeroPhysicsCallback | 拆解为三层 | 状态读取分支迁入 StateSource 的 Isaac 实现。模型求值与滑流编排迁入 AeroOperator 实现。力的施加、步界通报与回调壳迁入 SimBackend 的 Isaac 实现。held_body_vel 的滤波速度口径迁入 StateSource。 |
| _drive_wing_joints | 执行器层 | 迁入 Actuator 的 Isaac 实现。九关节目标计算、频率同步、频率差动注入、翼幅差动注入、门控注入、滞后差动注入与尾舵指令写出全部随迁。 |
| _ident_stream_write | 记录器层 | 记录器不属于四个抽象基类。它作为独立记录器模块先行迁出主程序，输入仍为快照字典，九十三列档案格式不变。 |

补充两行的归属如下。TailFuselageAero 迁入气动算子层，作为 AeroOperator 实现内的尾翼与机身部件。HoverPDController 保留在 aero_solver 内部并维持默认关闭，它不进入契约面。

## 六、迁移顺序建议与理由

迁移顺序为记录器、执行器、气动算子、仿真后端。每步迁移完成后立即跑悬停基准回归，回归不过则回退该步。

第一步迁记录器。理由有三条。第一，_ident_stream_write 的输入是快照字典，输出是逗号分隔值文件，它与控制回路没有反馈耦合，迁移风险在四件中最低。第二，它占主程序约两百行，迁出即可完成主程序拆分的第一段。第三，先迁记录器使后续每一步迁移都有完整数据流留痕，判据先于数据与失败证据先存档两条纪律因此有载体。

第二步迁执行器。理由有三条。第一，_drive_wing_joints 是控制器输出的纯下游消费者，把它包进 Actuator 不触碰 FlightController 的任何一行，满足平行新增不动生效基线的纪律。第二，等价性可以直接核对，现行 drive_diag 日志与关节目标缓存提供了逐拍对照物。第三，迁完后控制器输出到关节目标的通路定型，翼面指令九键成为事实上的稳定接口，气动算子的指令面随之可以冻结。

第三步迁气动算子。理由有三条。第一，气动双栈合并必须先有冻结接口，前一步已把指令面定稳，AeroOperator 的接口此时冻结代价最小。第二，翼面气动存在多流型多实现，接口冻结后双栈合并不改变悬停回归与差动偏航两个钩子的结果，合并风险受控。第三，气动求值运行在物理回调内部，改动风险高于前两步，放在迁移方法经过前两步验证之后。

第四步迁仿真后端。理由有三条。第一，SimBackend 组合其余三个部件，它的实现依赖前三个契约稳定。第二，最终验收判据要求同一控制器跑在两个后端上，后端必须最后落位才能执行该判据。第三，纯 Python 模拟后端以契约测试进持续集成收尾，放在最后使持续集成一次覆盖全部四层。

## 七、最终验收判据

验收判据共三条，全部满足时 I-014 按其关闭流程关闭。

第一条，同一个 FlightController 类不加修改，在 Isaac 后端与纯 Python 模拟后端各自跑通悬停基准，悬停基准的判据沿用现行悬停回归文本，运行后不许改判据。

第二条，tools/test_contracts.py 契约测试进入持续集成，提交动作自动运行该脚本，脚本失败即阻断提交。

第三条，控制器源码中不再存在自带的坐标系换算副本，换算唯一入口为 StateSource 的两方法与体轴字段，以源码检索无可疑换算段为核查方式。

## 八、坐标系纪律条款

状态源契约执行下列五条纪律，依据为 docs/交接说明_纪律与下一步.md 第一节第四条的口径检查要求，以及二零二六年九月二十九日转弯线的两起读数口径事故记录。

第一条，每个状态量必须携带 frame 字段，取值以 STATE_QUANTITY_FRAMES 的声明为准。

第二条，机体系与世界系的换算唯一入口为 StateSource 的 world_to_body 与 body_to_world 两方法，以及 read 返回结构中的既有体轴字段。

第三条，控制器侧禁止自行换算坐标系，禁止以部分欧拉角近似完整旋转，二零二六年九月二十九日世界系滤波速度被误作体轴速度的事故即该禁止的来源。

第四条，同一步内控制器、记录器与看板等多个消费者必须取得同一份读数，双源读数分歧按现行对账探针的口径处理。

第五条，四元数列与欧拉角列的装填必须逐列核对，二零二六年九月二十九日姿态列错装四元数分量的事故在迁移后不得复发。

## 九、实现与测试载体

契约的代码载体为 modules/contracts.py。契约的自检脚本为 tools/test_contracts.py，脚本覆盖三项断言：四个基类均不可直接实例化；实现全部抽象方法后可实例化；StateSource 返回结构含坐标系籍贯字段且校验器能拒绝缺失籍贯的结构。
