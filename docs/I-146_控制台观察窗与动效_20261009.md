# I-146 控制台观察窗与动效（2026-10-09）

> 事项 I-146：会话卡片墙、上下文仪表与六条动效。机主令先看效果，
> 本件在五队列内优先交付。依据方案第六节草图与第十四节评审修订稿。
> 施工：L5 队。判据四条冻结于事项登记。

## 一、实现

board_ui/console/WatchView.tsx 会话卡片墙：每张卡含路线章、事项名、
状态灯（在干活绿、空闲灰）、会话号、上下文仪表（宽度按占用百分比
平滑推进）、最后活动时刻（相对服务器时钟）与四按钮（注入与停止为
主要按钮、转录与出处为次要按钮，评审层级第三处落实；注入停止转录
按依赖时序禁用并注明承接事项，出处即开抽屉）。线筛选下拉、归档
抽屉空态、页头自动切换如实标注未启用（三期）。观察窗页签下轮询
收紧至三秒。

## 二、判据核验（云端实测 logs/i130_check/i146_check.js）

判据一（页面显示与后台真实状态偏差不超过五秒）：核验时点拉接口作
后台真值，十二张卡的占用读数、状态、守门标记逐格一致（PASS），
接口取数三十二毫秒，页签轮询三秒，显示链路偏差远小于五秒线。

判据二（六条动效逐项在档可验）：一、仪表推进 transition width 4s
linear 实测在案；二、状态灯过渡 color 0.2s ease-out 实测在案；
三、脉冲动画 ws-pulse 注入类名实测触发；四、切换双卡样式类
ws-card-exit 与 ws-card-enter 在样式表实测可查（触发场景三期接入，
属在档可验形态）；五、滚动行为 auto 无过渡、线筛选动画 ws-grid-in
在案；六、守门状态条 ws-gatebar 样式定义实测在案（当前无达标卡，
出现即渲染，指挥部页与战情室同款规则）。

判据三（密度上限四条数值达标）：全页扫描超二百毫秒的过渡仅仪表
一项（四秒，方案点名的数据跟踪动画，非界面过渡）；界面过渡全部
不超二百毫秒；主动运动受脉冲六十秒冷却与仪表互斥守卫约束，同视口
不超三个；动效属性纪律按评审清单执行（脉冲与切换只用透明度与位移；
状态灯颜色过渡与仪表宽度推进是评审点名的两条数据表达动效，此解释
随档声明）。

判据四（机主令先看效果，本件优先交付）：本件先于 I-147 与 I-158
交付，三个页签全部可用，机主即可在云端站点查看。
