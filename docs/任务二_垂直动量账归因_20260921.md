# 任务二：垂直动量账残差归因报告（2026-09-21）

## 一、结论

**残差既不是估算伪影，也不是物理侧存在真实的未登记垂直力；残差是记账口径缺陷：
CSV 的 Fz 列记录的是"每次回调点火施加的分摊值"（模型力 ÷ 点火率 ≈ 模型力 ÷ 2），
而机体每个物理步实际收到的是"合计值"（= 模型力）。账本把分摊值当合计值对账，
缺口 = 模型力 × (1 − 1/点火率) ≈ 模型力/2 ≈ +1.05 N。**

用 2×Fz 列修正口径后，垂直动量账闭合到 **−0.003 N（体重的 0.15%）**。
物理侧施力缩放修复（第七班"点火率缩放"）本身是工作的：机体确实收到了
F_model（均值 2.116 N ≈ mg = 2.109 N，与 64 秒近零平均垂直加速度自洽）。

## 二、账本复现（诚实基线 ident_stream_flight_0921_014141.csv）

- 门控：z>0.3 m 且 pin==0 的连续空中段；主段 64.0 s / 5759 样本 / 119 Hz（记录率已修复）。
- 质量口径：m=0.215 kg（215 g 平台），mg=2.109 N。
- 差分账：r(t) = m·a_z − (Fz − mg)，中心差分。
  **残差均值 +1.055 N，中位 +0.919 N，std 0.78 N** —— 复现任务书所述 ~+1 N 系统差。
- 冲量账（判别器，不做差分）：∫(Fz−mg)dt = −67.26 N·s，m·Δvz = +0.27 N·s，
  缺口 −67.5 N·s ≡ 均值 −1.056 N —— 与差分账一致。

## 三、三条假设的判别

| 假设 | 方法 | 结果 | 裁定 |
|---|---|---|---|
| H1 速度振荡导致的估算伪影（任务书首疑） | 冲量式对账（差分免疫）；平滑窗宽 0.1→2 s 敏感性；拍频+谐波带阻后重算 | 冲量式同样缺口 −1.056 N；残差均值在所有窗宽下恒为 +1.05 N（std 随窗宽坍缩 0.78→0.086）；带阻后 +1.055 N 不变 | **否决**。差分/振荡类伪影无法在冲量式中存活 |
| H2 拍动翼面垂直惯性力（25.1% MTOW 拍动质量，base_link 速度不含翼面振动） | 用记录关节角 flapLa/flapRa 二阶差分 × URDF CG 半径 × MASS_TABLE 估算 F_wing,z，并与残差对相关 | 翼面惯性力周期均值 +0.002 N；与残差相关系数 −0.20 | **否决**。对称拍动的垂直惯性均值抵消 |
| H3 真实的未登记垂直力（系留/接触/重力/质量失配/施力管线） | tension 列全零（系留关）；空中段无接触；残差对 (a_z+g) 回归斜率 0.140 kg 与"质量减半"预测 0.1075 接近但非常数残差；逐步回归 (m·a+mg) 对 Fz 列 | **斜率 = 1.998**（四份记录 1.994~2.010，corr 0.67~0.82）：机体每步收到的力 = **2×Fz 列** | **改判为记账口径缺陷**（见第四节）。物理侧无隐力：悬停自洽（2×1.058 = 2.116 ≈ mg） |

补充：残差与 vz 无关（回归斜率 +0.002 N/(m/s)）；按 60 样本滚动中位分段，
爬升/平飞/下降三段残差均值为 +1.047/+1.022/+1.054 N —— 残差是全局常数，不随飞行状态变。

## 四、根因链（代码证据）

1. `modules/aero_solver.py` 施力段（约 884-897 行）注释明确记载：气动回调在每个
   `world.step()` 内被点火多次（历史实测约 1.75 次/步、随渲染率漂移），而 PhysX
   外力累积器按步清算，逐火施加会把力放大该倍数。修复方案 = 主循环经 `main_step`
   通报步界，回调实测"每主步点火数" `_fpms`，施加力除以 `_fpms`。
2. 本批四份记录（0921_010220/011826/012142/014141）的逐步回归给出
   **点火率恒为 2.0**（斜率 1.994~2.010）。
3. 缺陷点：施加后代码执行 `self.last_F_world = F_apply`（缩放后的单次值），
   **覆盖**了缩放前的合计值；CSV 的 Fz 列取自 `last_F_world`。
   于是 Fz 列 = F_model/2，机体实收 = F_model，账本收入侧低记 2 倍。
4. 交叉验证：`last_F_raw`（钳位前原值）均值 3.65 N（Fwz+Ftz），经爬升守卫/钳位后
   F_model ≈ 2.1 N，与"实收 = mg"自洽；水平方向力小（~0.1 N 量级），故水平账
   此前能闭合到 ±0.06 N 而垂直账露馅。

## 五、修正口径与复算

- 修正：账本收入侧用 2×Fz（或等价地 × 实测点火率）。
- 复算：mean[m·a_z − (2·Fz − mg)] = **−0.003 N**（原 +1.055 N）。
- 结论：**"力真值在我们手里"的大厦成立——力没有被隐性地多加或少加，
  脏的是记录列的语义，不是物理。**

## 六、修复建议（本轮未改代码，按任务边界只提交建议）

1. 首选：CSV 增加 `Fz_model`（缩放前合计值）、`fire_rate`（_fpms）两列，
   Fz 列保留现状并改名 `Fz_per_fire`，杜绝歧义。
2. 次选：`last_F_world` 不再被 F_apply 覆写，另设 `last_F_applied_per_fire`。
3. 账本侧临时修正系数 2.0 已在四份记录上验证稳定，但点火率注释明言随渲染率
   漂移，**不建议长期硬编码 2.0**，以 fire_rate 列为准。
