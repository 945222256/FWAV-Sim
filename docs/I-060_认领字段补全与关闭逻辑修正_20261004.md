# I-060 认领字段补全与关闭写入逻辑修正（2026-10-04）

> 事项 I-060：I-053 与 I-056 关闭时 claimed_by 为空而 claimed_at
> 有值。本文件为交付记录。销项判据为补全两条记录字段并修复写入
> 逻辑，保证以后的完成记录都必须带执行人，修复并验证。

## 一、缺陷与成因

两条完成记录的认领人字段为空、认领时间为有值。成因在关闭写入
逻辑：云端与本地两条关闭通道落库时只写结载人字段，不检查认领人
字段，认领人缺位的事项被关闭后，完成记录的责任链缺一环。

## 二、修复内容

构造级修正：两条关闭通道在落库时检查认领人字段，缺位即由结载人
补位，认领时间缺失时同刻补记。修正后完成记录在结构上不可能不带
执行人（结载人字段本为必填，认领人缺位时继承结载人身份）。修改
文件为 cloud_board/api_ledger.py 与 items_registry/ledger.py，云端
已部署重启。

## 三、补全与验证实录

历史记录补全为服务器侧一次性脚本执行，执行前数据库整体备份：
I-053 认领人由空补为 L3看板会话（与结载人一致），I-056 同。补全
后接口复验两条记录认领人与结载人一致。写入逻辑验证在账本文件
副本内完成（不触碰真账）：构造认领人缺位的草稿事项执行关闭，关闭
后认领人字段被结载人自动补位、认领时间同刻补记，验证通过。

## 四、判据对照

判据要求补全两条记录的字段并修复写入逻辑、保证以后完成记录必须
带执行人、修复并验证：三条逐一落实，见第二节修复、第三节补全
实录与副本验证。
