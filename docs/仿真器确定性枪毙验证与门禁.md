# 仿真器确定性：枪毙验证与永久门禁（2026-09-28 午后，机主令）

机主令：不允许任何抽奖行为；同一初值在当前仿真中算出来必须一样。
本文件记录执行与判决。

## 一、概念分界（判决的逻辑基础）

两个此前被混在一起的概念必须分开。

其一，非确定性：同一二进制、同一配置、同一初值，两次运行结果不同。
这是仿真器实现层的缺陷类问题（跨线程调度竞态、求解器内部顺序），
不是物理，不是数学必然，没有任何理由被容忍。本次枪毙的对象。

其二，混沌灵敏度：这架飞机的开环横向动力学是放大器（李雅普诺夫
增长率为正，已实测分档）。这是被控对象的物理属性，不是仿真器的
缺陷。在确定性仿真器上，同一初值永远给出同一轨迹，抽奖不存在；
灵敏度只在我们改动任何东西（配置、代码、平台）时体现为结果差异，
那恰恰是它该有的样子。

## 二、执行与判决

在隔壁已实装的 FLAPPER_PHYS_CPU（强制中央处理器动力学）基础上，
本班补尝试 PhysX 确定性开关系列并实测：配置接口显示确定性标志
在本版本默认已置位、图形处理器动力学默认关闭。判决运行：
中央处理器加确定性模式下，同一配置背靠背四跑三十秒（窗口覆盖
此前七点六秒分岔点与巡航时界），全精度侧档逐位对比：
四份文件逐字节一致。判决：该配置下确定性成立。

对照事实：默认模式历史上出现过背靠背分岔（第七点六秒）与十连跑
九分之一概率分岔。因此门禁按模式区分：确定性承诺只在
FLAPPER_PHYS_CPU=1 加确定性标志的配置下成立。

## 三、永久门禁（即刻生效，写入交接说明）

1. 一切验收、判别、标定类在环运行，必须使用 FLAPPER_PHYS_CPU=1，
   并且背靠背复跑一次，全精度侧档逐字节一致，两者缺一即整组作废。
2. 门禁工具：tools/ 下复用 detcheck 侧档对比（本班验证脚本口径）。
3. 承诺边界（诚实声明）：逐位一致只在同机器、同构建、同配置下
   承诺；跨机器、跨版本升级后必须重做背靠背验证。间歇事件的
   概率估计样本尚小，门禁规则的兜底语义是"不一致即作废"，
   不依赖概率估计。
4. 李雅普诺夫增长率保留为被控对象的物理诊断量继续测量，但它
   从此是飞机的属性描述，不再是任何单次结论的借口。

## 四、对既有结论的回收规则

门禁生效前的全部单次在环结论按隔壁定则处理：时界内的机理观察
保留，时界外的存活与成败类结论一律以统计口径重跑后才准引用。
巡航六十秒基线按"边缘幸存"口径引用（隔壁 E0 已在案）。
