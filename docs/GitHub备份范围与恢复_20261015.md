## 本次备份方式

远端原为空仓库。本地旧历史已经包含缓存、大体积求解结果和历史运行材料，因此首次上传采用经过筛选的当前文件快照，建立独立的 `github-backup` 分支并上传为远端 `main`。它不携带本地 `master` 的旧提交祖先。本地原分支、提交历史、工作文件和已有暂存区均保留；不改写历史，不删除实验数据，不切换正在工作的分支。

当前备份是一份开发状态备份，包含多岗位尚在推进的工作；提交成功不能作为生产发布、仿真验收或事项关闭的证据。

## 恢复与后续备份

从 GitHub 克隆 `main`，按需执行 `git submodule update --init --recursive` 恢复第三方资源。Isaac Sim、浏览器、Python/Node 环境和认证凭据需要在目标机器独立安装或配置。大体积本地资源、运行账本和被排除的实验数据不能由这份源码备份完整恢复。

后续在开发工作区执行 `python -B tools/github_backup_publish.py`，先筛选并扫描，再生成一个以现有 `github-backup` 为父提交的新快照；确认本地输出结果后，以 `git push origin refs/heads/github-backup:refs/heads/main` 上传。上传后必须回读远端提交号。不要使用 `git push --all`、`--mirror`，也不要直接把旧 `master` 推到公开仓库。

此次只完成 GitHub 备份，不发布或重启生产看板服务。
