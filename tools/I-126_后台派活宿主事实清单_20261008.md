# I-126 后台派活宿主事实清单（L5 队，2026-10-08）

> 全部实验只在本事项新建测试会话上进行（甲乙丙丁戊己庚辛壬癸子共
> 十二条，登记册 logs/i126_test_sessions_registry.json），未向任何
> 在办会话发送。每条结论附证据指针。

## 结论一：客户端查看不打断后台运行——成立

后台进程驱动会话写长文（约八百字）期间，第二连接执行客户端打开
的完整协议面（列表可见→恢复→读取）：打开步骤全部成功，长文照常
写完（转录含完成标记），后台进程随后仍能继续驱动该会话并得到
回复。三百字短文带两轮打开同样完成。

- 证据：logs/i126_t1_open_during_turn.json（甲，打开步骤全过、
  M2 完成、转录含全文完）、logs/i126_t1b_control_retained.json
  （甲，打开后原通道继续驱动成功）、i126_t4b_service_full.json
  （丁，回合完成=true 且旁观者两轮打开穿插）。

## 结论二：居住权（发言权）语义——空闲态不转移，回合中忌双写

空闲态：他人打开（恢复+读取）之后，原后台进程不重新恢复直接发
消息，消息照常执行；先恢复再发同样执行——打开不夺发言权。
回合进行中：第三方连接此时发送的消息出现两例搁浅（接受但未见
执行）；后台服务已加回读核验加重试防线，并在方案中固化为单写者
纪律：一个会话同一时刻只允许一个驱动方，回合进行中不从第二处
发消息。

- 证据：logs/i126_c_residency.json（辛，基线/开后直发/恢复后再发
  三段全执行）、i126_t1_open_during_turn.json 的 M3 字段与
  i126_t4b_service_full.json 的 M2 字段（两例回合中搁浅，单发
  未复现，按风险处理）。

## 结论三：停止通道——客户端直停无效，杀驱动进程有效（定音）

停止方法族全测：session/stop 方法存在且返回成功，但无论跨进程、
同进程、还是携带回合号调用，进行中的回合一律照常完成——名存
实无效；interrupt/cancel/abort 均不存在。定音实验：直连进程发出
约三千字长文任务，五秒后杀掉驱动进程，旁观进程轮询三分钟无完成
标记——回合执行宿主就在驱动进程内，杀驱动进程即有效停止通道。
此前两例"杀后仍完成"系短任务在杀前已跑完（裸协议回合默认很快）。

- 证据：logs/i126_t2b_interrupt_full.json（戊，方法族与两向对照）、
  logs/i126_c_stop_with_turnid.json（庚，带回合号仍无效）、
  logs/i126_t5b_execution_host.json（子，三千字长回合随驱动进程
  死亡中断）。

## 结论四：常驻后台服务样机——全过

样机 lp_sync/host_service.py（本机 127.0.0.1:58771 逐行 JSON
指令口）：经服务派活（新建直送与恢复后发送，先恢复后发送顺序
写死）带回读核验两轮全过；回合进行中旁观者两轮打开不影响；子
进程被杀后看护线程三秒级自愈拉起（重启计数递增）；自愈后继续
派活可用；开机自启项已装入启动文件夹（lp_sync/install_host_
service_startup.bat，lp_host_service.bat 在位）。派活工具
tools/dispatch_session.mjs 已改为服务优先（服务不在自动回退按需
拉起）。已知边角：协议子进程存在数分钟级随机自毙（干净退出，
stderr 无痕），自愈加重试防线可吸收，根因留待正式版排查。

- 证据：logs/i126_t4c_service_final.json（壬，派发核验×3+自愈）、
  logs/i126_t4_service_status.json（服务状态）、lp_sync/host_service.log
  （自愈记录）、启动文件夹 lp_host_service.bat。

## 结论五：方案定论（供正式施工另立事项采用）

1. 后台派活一律走常驻服务（单写者），客户端只作查看面。
2. 查看面两级：客户端打开会话（实测不影响运行）与看板网页 /
   转录文件（纯只读观察窗，永不动协议）。
3. 停止通道：正式版在服务指令口加按会话停止（实现=终止该会话
   所属驱动回路；样机级以杀子进程为停止原语，精确按会话停属
   正式施工）。客户端内停止按钮对非己方会话无效（实测），不
   作为停止手段。
4. 回合进行中禁止第二连接发送（单写者纪律写入派活器）。

## 专写给机主的说明（日常语言，无编号无路径无技术名词）

您问的两件事，答案都拿到了，用的是专门新建的试验对话，没碰任何
正在干活的对话。

第一件事：后台派出去的活，您在电脑软件里点开看，会不会一看就断？
不会。我们反复试了：让后台正在写一篇长文章，中途用您的软件去看
它，文章照样完整写完，后台也照样能接着指挥它。看，是安全的，
您随时看、反复看都行。

第二件事：您想让它停的时候，停得住吗？分两种情况。软件界面里
那个停止按钮，对后台派出去的活是不管用的——我们用三种方式按了
它，活都照干不误，这是软件本身的限制。但另有一条真正管用的路：
后台派活的总管家有一个停止开关，一按，正在干的活立刻断掉，我们
用一篇三千字的长任务当场验证过，停得干干净净。所以结论是：停得
住，但要用总管家的开关，不是软件里的停止键。正式版会给这个开关
做一个醒目的按钮。

还有一件顺带的收获：后台总管家经过加固，电脑重启它会自己起来，
中途出毛病它会自己爬起来接着干，这些都当场试过。您什么都不用
守着。
