# 适配指南：从模板生成新项目的固定步骤

本指南定义把治理模板实例化为一个新项目的固定流程。全部步骤按序执行，不跳步。本指南自身不含任何具体项目的内容。

## 模板包的构成

模板包分三层：

1. registry 机制层：dispatch 认领与租约、ledger 总账读写、events 事件流、schedule 依赖图、intake 待审队列、langcheck 语言检查、check_commit 领地自查、bootstrap 初始化器。
2. governance 制度文本层：协作架构、汇报标准、语言规范、指挥部原则、总计划、强制指令六份填空模板。
3. board 触达层：本地只读看板与扩展占位说明。

机制层与制度文本层不含任何项目专属内容；项目专属内容全部在数据文件与制度文本的占位符里。

## 第零步：初始化

命令：python template/registry/bootstrap.py <新项目根目录>

该命令把机制层拷入新项目的 registry 目录，生成空总账、空待审队列、空事件流与待填的路线表，同时拷入制度文本层与触达层。

## 第一步：路线划分

编辑 registry/lanes.json：

1. 每条路线填名称、一句话使命、归位关键词、独占路径。
2. 路线数量由项目工作分组决定，指挥部路线必留。
3. 独占路径是各路的施工领地，共享路径保留 tools 与 logs 两条为最小集。
4. 判定标准：任何两个路线的独占路径不能互为前缀。

## 第二步：项目配置

编辑 registry/data/config.json：

1. project_code 填项目代号。
2. env_prefix 填本项目环境变量统一前缀。
3. acronym_whitelist 登记本项目专属英文缩写。
4. tool_data_globs 登记本项目其他登记库的工具写入豁免路径。

## 第三步：词表填写

编辑 registry/banned_words.json 与 registry/glossary.json：

1. 比喻词、内部压缩词按本项目沟通病史填写，废止编号按本项目历史编号习惯填写。
2. 术语登记册收录本项目全部专属术语与英文缩写。

## 第四步：制度文本实例化

把 governance 目录六份模板中的尖括号占位符替换为项目内容：

1. 协作架构：补齐角色队名与领域强制前提节。
2. 汇报标准与语言规范：核对执行点命令路径后即可直用。
3. 指挥部原则：填项目总目标与首批决定。
4. 总计划：填方向、卡点与首批事项表。
5. 强制指令：填统一运行入口与标准锁；没有则删除该文件。

## 第五步：首批事项登记

按待审队列流程登记首批事项：

1. 提交走 intake 的提交接口，目标上下文与完成判据必填。
2. 审理跑 lint 四规则。
3. 批准入册必须附机主说明，不少于六十字，内容为四句：做了什么、结果是什么、为什么是这个结果、下一步是什么。

## 第六步：开工验证

新项目骨架可用的判定清单，全部通过才算实例化完成：

1. 看板命令能列出本路队列：python registry/dispatch.py <路线编号>。
2. 依赖图校验通过：python registry/schedule.py。
3. 领地自查自检通过：python registry/check_commit.py --selftest。
4. 语言检查对样例文本通过：python registry/langcheck.py --msg "样例"。
5. 只读看板能启动并显示首批事项：python board/server.py。
6. 一个判据脚本能对新项目骨架的真伪做出判定并输出结果。

## 完成机制速查

- 登记事项：intake 提交、lint 审理、批准入册三步。
- 认领：dispatch 认领接口，默认租约四小时，一路一时只持一个进行中事项。
- 完成关闭：总账关闭接口，必须附证据、结论、判据逐条对照与机主说明。
- 卡住申报：总账卡住接口，五种阻塞类型选一，写明解除需要什么。
- 汇报：七段格式，见《汇报标准》。
