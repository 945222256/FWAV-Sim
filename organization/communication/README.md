# 标准联络入口

适用：Isaac flapper sim 的经理、专业岗位和顾问。2026-10-14 机主明确委托 Elsa 建立并注册标准联络工具；岗位权限仍以当前入职卡和具体授权为准。

正常传话优先调用 `manager_comms.send_manager_message`，直接给姓名和固定字段。工具内部读唯一通讯录，不需要先搜索会话列表、读聊天历史或提取会话号。工具不可见、联系人地址缺失或发送失败时，先报告具体接入问题；修复通讯录或检查运行状态时可按授权使用会话查询，不默默猜地址发送。

## 固定字段与字数

只允许两种联络：**执行任务**，必须写对方现在可做的具体动作；等待、待命、收到或知悉不算动作，缺材料时由负责方就绪后再交接。**机主信息移交**，必须引用机主明确要求向该人转交该信息的原话，收件人无需操作、无需回复。普通进度不发送。

接收任务直接执行，返回结果或具体阻碍；接收信息移交无需回复。两者都不发送“收到”或复述来信。每条消息自动附对应接收规则，岗位背景与技能同时说明。字段与常见等待表达由程序检查；动作是否真正可执行、授权原话是否真实仍由调用者核实。发送端校验不能保证接收模型绝不输出收悉，不能把规则已写入当成接收行为已验证。

| 字段 | 含义 | 限制 |
|---|---|---|
| sender | 当前岗位固定人员标识 | 必填，须在通讯录；不能冒称他人 |
| to | 收件人姓名或固定标识 | 必填，由后台解析地址 |
| purpose | 本条消息的用途 | 仅执行任务、机主信息移交，选择一项 |
| item_id | 关联事项 | 可选，I 编号；普通联络不伪造编号 |
| summary | 发生了什么、具体问题是什么 | 必填，最多80字 |
| action | 对方现在要做什么 | 执行任务填写具体动作，最多80字；机主信息移交固定填“无需操作，无需回复。” |
| details | 必要补充 | 可选，最多100字 |
| evidence | 证据入口 | 最多2个已存在项目相对文件路径或 https 链接，不贴日志 |
| authorization | 已有机主授权依据 | 必填，后台留痕；机主信息移交须引用明确转交指令原话，一般岗位授权不足以代替 |
| request_id | 稳定请求号 | 可选；未填按内容及授权生成，同一意图自动去重 |

摘要、动作和补充合计不超过240字；含证据入口的消息总长度不超过700字。按 Unicode 字符数计数，含标点和空格；字数不是 token 数。字数只在发送者回执中显示，收件正文用自然短句，不显示字段标签或“姓名 → 姓名｜用途”的标题。

表达须为完整短句，说明具体问题与接续动作。版本号和条款序号放在证据入口中，不能用“原第四条”“第五版”等替代说明；用“独立复核”及明确触发条件代替“独立回收”。会话号、布尔状态串、秒级执行时间留在后台审计。固定字数和已列出的表达模式由程序严格检查；语义是否完整仍须发送者判断，不能声称所有中文表达质量均可自动证明。

## 最短调用

```json
{
  "sender": "elsa",
  "to": "Doro",
  "purpose": "执行任务",
  "item_id": "I-186",
  "summary": "二队已提交输入来源与结果记录的修复材料。",
  "action": "请独立复核所附交付材料，并登记结论。",
  "authorization": {
    "basis": "填写本次已有机主对对象和动作的明确授权出处"
  }
}
```

例子说明格式，不授权发送。所有字段在同一次调用中填写，正常直接调用发送工具一次，内部完成校验、查通讯录、正文渲染和投递；不逐字段调用，不要求先预览、再发送。只有查看样式或排查输入时才用 `preview_manager_message`，它只读，不发送。

上例收件人看到：

> Doro，我是 Elsa。关于 I-186：二队已提交输入来源与结果记录的修复材料。
>
> 请独立复核所附交付材料，并登记结论。
>
> 请直接执行，返回结果或具体阻碍；无需确认收悉。

姓名、目的、关联事项和字数仍保存为结构化字段，供回执与后台审计使用。发送者只填写摘要和动作，不在其中重复手写标题或字段标签。

## 状态与恢复

`queued` 只证明通道受理，不能写成已送达、已处理或事项完成。重复请求返回原状态并明确未重发。请求在外部发送前先以原子事务保存，发送后进程退出或通道超时时保留 `pending` 或 `result_unclear`，须先对账，不自动生成新编号重发。

详细路由、授权、操作系统调用者、声明岗位、正文和通道结果写入 `logs/manager_communications/messages.sqlite3`。默认 sender 是岗位声明，不能证明实际调用会话身份；选择绑定岗位的独立启动配置后，服务拒绝其他 sender，但仍不代替机主授权。

## 各岗位背景与生效

各岗位独立背景模板见 `role_prompts.json`，依据现行通讯录与入职卡生成。注册程序为每个岗位安装 `isaac-manager-人员标识` 启动配置；使用相应 profile 才会加载该岗位的背景指令与绑定 sender。保存模板不会自动改写正在运行的对话。

公共默认入口由项目背景指令文件、`project-manager-messaging` 技能和工具初始化 instructions 提供。工具 schema 及服务端校验约束经过本工具的请求，背景指令引导选择工具；其他发送入口仍由宿主保留，因此不能承诺所有现有会话每次都被技术强制走此工具。工具不可见时在宿主重新加载协议连接并核对，不重启其他施工服务。
